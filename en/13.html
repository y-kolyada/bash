    Questions · Noob

    Fifty foundational questions with concise answers. Each includes a note on why it gets asked: often more valuable than the answer itself.

    Key idea of this page #

    Questions at this level test operational mechanics rather than memory: why a local file fails to execute, why quotes are mandatory, and why cd inside a script does not change your terminal's directory. Answer concisely and directly - over-explaining simple mechanics signals uncertainty. The “why this gets asked” note reveals the underlying principle being tested and anticipates the likely follow-up question. If an answer seems unfamiliar, the corresponding walkthrough is available on the Noob examples page.

    Execution, files, and paths (1–10) #

    1. What does the first line #!/usr/bin/env bash do?
      It informs the kernel which interpreter to use when executing the file. The env form searches for Bash across PATH, rather than hardcoding /bin/bash.
      Why this gets asked: tests whether you understand that a script is an ordinary file rather than a distinct file type.
    2. Why does script.sh fail to run, while ./script.sh executes?
      Without ./, the shell searches directories listed in PATH, which does not include the current directory.
      Why this gets asked: the most common initial beginner error; verifies understanding of PATH.
    3. What is the purpose of chmod +x?
      It sets the execute permission bit. Without it, the file can only be run via bash script.sh.
      Why this gets asked: distinguishes file existence from execution privileges.
    4. How does ./script.sh differ from bash script.sh?
      In the first case, the interpreter is determined by the shebang and execute permissions are required; in the second, bash itself executes with the script as an argument.
      Why this gets asked: verifies understanding of process spawning and interpretation.
    5. How does . (dot) differ from ./script.sh?
      . script.sh or source executes the file within the current shell environment, preserving its variables; ./script.sh spawns a separate child process.
      Why this gets asked: explains why cd inside a script does not change the caller's terminal directory.
    6. What is PATH?
      A colon-delimited list of directories where the shell searches for executable programs.
      Why this gets asked: fundamental concept; required to troubleshoot “command not found”.
    7. How do you determine which program will execute for a given command name?
      type cmd or command -v cmd: displays the path, alias, function, or shell builtin.
      Why this gets asked: verifies whether you diagnose root causes rather than guess.
    8. How does a script locate its own containing directory?
      dir=$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd). The current working directory is where the script was invoked from, not where it resides, and relative paths inside evaluate against the former.
      Why this gets asked: the most frequent practical question when writing production-ready scripts.
    9. How does an absolute path differ from a relative path?
      An absolute path starts with / and is independent of working directory; a relative path resolves relative to the current working directory.
      Why this gets asked: scripts almost always require absolute paths or explicit anchors.
    10. How do you view command documentation?
      man cmd for system binaries, help cmd for Bash builtins, cmd --help for most standard utilities.
      Why this gets asked: checks whether you know that shell builtins do not appear in man.

    Variables and quoting (11–20) #

    1. How do you declare a variable and what characters must not surround the assignment?
      name=value, with no spaces around =. Adding a space causes the shell to interpret the variable name as a command name.
      Why this gets asked: classic beginner syntax mistake, immediately apparent.
    2. Why must variables be enclosed in quotes like "$var"?
      Without quotes, the value undergoes word splitting on whitespace/newlines and pathname expansion. A path with spaces fragments into multiple arguments, and *.log expands into directory listings.
      Why this gets asked: the leading cause of bugs and security vulnerabilities on production data.
    3. How do double quotes differ from single quotes?
      Double quotes allow parameter and command expansions; single quotes preserve text literally.
      Why this gets asked: tests understanding of when expansions occur.
    4. What does ${var:-default} evaluate to?
      Default value expansion: if the variable is unset or null, it evaluates to default.
      Why this gets asked: the most common idiomatic pattern to prevent crashes on empty variables.
    5. How does $var differ from ${var}?
      Braces disambiguate variable names from adjacent characters (${var}_x), and are mandatory for positional parameters beyond nine: $10 evaluates as $1 followed by literal 0, whereas the tenth parameter is ${10}.
      Why this gets asked: checks whether you understand where token identifiers terminate.
    6. What is command substitution?
      $(cmd) captures the standard output of a command and substitutes it into the string. Backticks are deprecated: nesting them requires cumbersome escaping.
      Why this gets asked: the foundation of computing dynamic inputs in shell scripting.
    7. What does $? store?
      The exit status of the most recently executed command: 0 represents success, non-zero represents error.
      Why this gets asked: prerequisite for control flow and decision-making on results.
    8. What do $1, $@, and $# represent?
      The first positional argument, all positional arguments, and the total argument count.
      Why this gets asked: foundational toolkit for parametrized scripts.
    9. How do you make an environment variable available to child processes?
      export VAR=value. Without export, the variable remains private to the current shell process.
      Why this gets asked: explains why child binaries fail to see shell-assigned variables.
    10. What is an alias and why does it not work inside scripts?
      A command shortcut for interactive shells. By default, aliases are not expanded in non-interactive scripts, and scripts do not source .bashrc where aliases are typically declared.
      Why this gets asked: verifies understanding of the boundary between interactive and scripted shells.

    Conditions and loops (21–30) #

    1. How do you test if a file exists?
      if [ -f "$f" ]; then …. Use -d for directories, and -e for any filesystem object.
      Why this gets asked: foundational pre-action validation pattern.
    2. What do the -z and -n operators check?
      -z checks if a string is empty; -n checks if a string is non-empty.
      Why this gets asked: argument validation almost always begins here.
    3. How does [ ] differ from [[ ]]?
      [ is a standard builtin command whose arguments undergo word splitting and globbing. [[ is a shell keyword with custom parsing: safe with empty strings, supports pattern matching, &&, and =~. Only [ is portable across all POSIX shells.
      Why this gets asked: classic interview question testing portability and parser mechanics.
    4. How do you compare numbers rather than strings?
      Use [ "$a" -gt "$b" ] or arithmetic evaluation (( a > b )). The > character inside [ ] acts as a redirection operator.
      Why this gets asked: an insidious trap that silently corrupts files.
    5. How do you iterate over files in a directory?
      for f in *.log; do … done - glob expansion is performed natively by the shell.
      Why this gets asked: checks whether you avoid the anti-pattern of parsing $(ls).
    6. Why should you never write for f in $(ls)?
      The output of ls is a raw string subjected to word splitting, breaking filenames containing spaces.
      Why this gets asked: textbook mistake, fails on the first encounter with production data.
    7. How do you read a file line by line?
      while IFS= read -r line; do … done < file.
      Why this gets asked: tests understanding of raw reading (-r) and whitespace preservation (IFS=).
    8. How do you trace what a script is actually executing?
      Run bash -x script.sh or set set -x inside: every command is printed after expansions, prefixed with +. This is vastly faster than scattering manual echo statements.
      Why this gets asked: essential debugging skill; without it engineers debug blindly.
    9. How do you implement branching across multiple pattern choices?
      case "$x" in a) … ;; b) … ;; *) … ;; esac - performs glob pattern matching.
      Why this gets asked: clean alternative to verbose if-elif chains.
    10. What do || and && signify between commands?
      && executes the right-hand command if the left succeeded (returned 0); || executes if it failed (returned non-zero).
      Why this gets asked: foundation of idiomatic one-liner checks and fallbacks.

    Files, text, and pipelines (31–40) #

    1. How do you find files by name across nested directories?
      find . -name '*.log' -type f.
      Why this gets asked: universal administrative command asked in every interview.
    2. How does grep differ from find?
      grep searches text contents inside files, while find locates filesystem entries by attributes.
      Why this gets asked: checks whether you conflate filesystem inspection with text parsing.
    3. What do the -i, -r, and -v flags do in grep?
      Case-insensitive matching, recursive directory search, and inverted match (select non-matching lines).
      Why this gets asked: the three most frequently utilized grep flags.
    4. How do you inspect the head and tail of a file?
      head -20 f and tail -20 f; tail -f streams real-time appended data.
      Why this gets asked: daily routine in log inspection and troubleshooting.
    5. What does 2>/dev/null do?
      Redirects standard error to the null device. Convenient, but dangerous: it suppresses diagnostic error messages needed to debug failures.
      Why this gets asked: appears frequently; tests whether you understand the hidden cost.
    6. How do you replace text in a file in place?
      sed -i 's/old/new/g' file. On macOS BSD sed, -i requires an explicit backup extension argument: -i ''.
      Why this gets asked: tests awareness of cross-platform differences between GNU and BSD tooling.
    7. How do you sort text and remove duplicate lines?
      sort file | uniq; uniq -c prefixes occurrence counts. Because uniq only collapses adjacent duplicate lines, pre-sorting is mandatory.
      Why this gets asked: classic mistake - running uniq without sorting first.
    8. What is a pipeline |?
      An inter-process communication stream: standard output of the left command is connected to standard input of the right; both execute concurrently.
      Why this gets asked: core pillar of Unix philosophy.
    9. How does > differ from >>?
      > truncates and overwrites the target file, while >> appends data to the end.
      Why this gets asked: one of the costliest single-character typos in systems administration.
    10. How do you direct both stdout and stderr into the same file?
      cmd > file 2>&1 - evaluation order from left to right is critical.
      Why this gets asked: verifies understanding of file descriptor duplication.

    Processes, permissions, and triage (41–50) #

    1. What are standard file descriptors 0, 1, and 2?
      Standard input (stdin), standard output (stdout), and standard error (stderr). Primary data streams through 1, diagnostics through 2.
      Why this gets asked: required to explain shell redirection and piping.
    2. How do you inspect running processes?
      ps aux or ps -ef; interactively via top or htop.
      Why this gets asked: standard daily troubleshooting routine.
    3. How do you terminate a process?
      kill PID transmits SIGTERM - requesting clean shutdown. kill -9 transmits SIGKILL, which cannot be caught or handled by the process.
      Why this gets asked: tests whether you distinguish polite termination requests from kernel termination.
    4. How does Ctrl+Z differ from Ctrl+C, and what do &, bg, and fg do?
      Ctrl+C sends SIGINT to terminate a command, while Ctrl+Z sends SIGTSTP to suspend it. bg resumes a suspended job in the background, fg brings it to the foreground, & launches it directly in the background, and jobs lists background tasks.
      Why this gets asked: beginners frequently press Ctrl+Z instead of Ctrl+C, leaving dangling suspended tasks.
    5. How do you check available disk space?
      df -h for filesystem capacity; du -sh * for directory usage.
      Why this gets asked: step one in triaging almost every production incident.
    6. What do rwx permissions signify?
      Read, write, and execute permissions for user owner, group, and others. chmod 755 grants full access to owner, and read/execute to group and others.
      Why this gets asked: baseline Linux systems knowledge.
    7. How does sudo differ from logging in directly as root?
      sudo executes a single command with elevated privileges while recording an audit log entry.
      Why this gets asked: security and auditability best practices.
    8. How do you inspect environment variables?
      env or printenv; individually via echo "$VAR".
      Why this gets asked: essential when diagnosing “works locally, fails in CI” disparities.
    9. What is cron?
      A daemon scheduler for periodic commands. Critically, it runs in a clean environment without sourcing .bashrc, resulting in a minimal PATH.
      Why this gets asked: perennial interview pitfall.
    10. How does a symbolic link differ from a hard link?
      A symbolic link (ln -s) stores the target path as a pointer and breaks if the target is deleted; a hard link is an alternate directory entry referencing the same underlying inode and functions only within a single filesystem.
      Why this gets asked: one of the most frequent Linux filesystem questions.
