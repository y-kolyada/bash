    Questions · Pro

    Fifty production-grade questions. Here interviewers no longer ask what a command does - they ask what will happen when it fails.

    Key idea of this page #

    Questions at the Pro level almost exclusively target failure modes: where set -e fails to trigger, where exit statuses get lost, what happens to containers upon termination, and why an environment variable from one CI step vanishes in the next. Answers cannot be memorized - they are derived from understanding process trees, file descriptors, and expansion ordering. Consequently, questions are grouped by failure domain rather than documentation chapters. If an answer seems unfamiliar, the corresponding technique is walked through on the Pro examples page, and the underlying mechanics in key components.

    Strict mode, errors, and signals (1–10) #

    1. What exactly does each option in set -euo pipefail do?
      -e exits on non-zero return code; -u treats unset variables as errors; -o pipefail sets the pipeline return code to that of the rightmost command to exit with a non-zero status.
      Why this gets asked: tests whether you understand these as three separate architectural decisions rather than a single magic incantation.
    2. Name the situations where set -e does not trigger.
      Inside if/while conditions, to the left of && or ||, inside functions invoked as part of a condition, in command substitutions evaluated in arguments, and in local x=$(cmd): the return code of local masks the command substitution's failure code.
      Why this gets asked: the quintessential reliability question; separates theoretical knowledge from production reality.
    3. Why is -E required alongside trap ERR?
      Without it, the ERR trap is not inherited by shell functions or subshells, allowing errors inside functions to bypass the error handler.
      Why this gets asked: rarely known; demonstrates hands-on debugging experience.
    4. How do you find the line number where a script failed?
      trap 'echo "line $LINENO"' ERR combined with set -E. Bash does not provide built-in stack traces.
      Why this gets asked: evaluates how you triage production failures.
    5. How do you obtain the exit code of a specific stage in a pipeline?
      From the ${PIPESTATUS[@]} array immediately following the pipeline - any subsequent command overwrites it.
      Why this gets asked: classic differentiator; separates those who have read man bash thoroughly.
    6. Why does a script with set -e silently exit on ((i++))?
      Arithmetic evaluation returns exit code 1 if the arithmetic result is 0, and post-increment i++ on i=0 yields 0. The safe form is i=$((i + 1)): variable assignments always return exit code 0.
      Why this gets asked: classic trap: the script crashes without a single error message on a loop counter.
    7. What does trap … EXIT do and why is it more reliable than manual cleanup?
      It executes upon any termination the shell can detect: normal completion, error exits, or signals. The exception is SIGKILL: under kill -9, the OOM killer, or abrupt container termination, the trap does not run and temporary files remain.
      Why this gets asked: checks whether you reason through all exit paths, including unpreventable termination.
    8. How does exit differ from return inside a function?
      return terminates the function; exit terminates the entire process. However, a function invoked via command substitution $( ) runs in a subshell, so its exit only terminates the subshell, leaving the parent script running.
      Why this gets asked: tests understanding of process isolation on the most common edge case.
    9. What does exit code 130 signify?
      Termination by signal: 128 + N where N is the signal number; 130 corresponds to SIGINT (e.g. Ctrl+C).
      Why this gets asked: demonstrates ability to read exit codes in CI logs.
    10. What is a zombie process and why does kill -9 fail to remove it?
      It is an already-terminated process whose exit status has not yet been collected by its parent via wait. There is nothing to kill - it is dead; it disappears once the parent waits on it or the parent terminates. In containers lacking an init system, nobody collects orphans, causing zombies on PID 1.
      Why this gets asked: connects signals, wait, and container PID 1 responsibilities in a single question.

    Expansions, arrays, and quoting (11–20) #

    1. How does "$@" differ from $@ and "$*"?
      "$@" expands to separate positional arguments preserving word boundaries; $@ splits on IFS; "$*" collapses all arguments into a single string separated by the first character of IFS.
      Why this gets asked: one of the most frequent interview questions; the answer instantly reveals skill level.
    2. Why do professional scripts prefer printf over echo?
      Behavior of echo with flags like -n, -e, or trailing backslashes diverges across shells and operating systems; printf is strictly defined by POSIX and behaves consistently.
      Why this gets asked: universal portability question asked in almost every assessment.
    3. Why include IFS=$'\n\t' at the start of a script?
      It restricts field splitting to newlines and tabs, eliminating whitespace splitting where it is almost never desired.
      Why this gets asked: a staple of canonical strict mode configurations.
    4. Why does arr=($(cmd)) fail and what should replace it?
      Command substitution output undergoes word splitting and glob expansion: whitespace-separated items split into multiple elements, and * expands to filenames. Replace with mapfile -t arr < <(cmd): one array element per line, with no globbing.
      Why this gets asked: distinguishes knowledge of array syntax from understanding why dirty data corrupts arrays.
    5. Why does df show a full disk while du shows ample free space?
      Two common causes: an unlinked file still held open by an active process prevents disk block deallocation while remaining invisible to du (locate via lsof +L1); and exhausted inode tables despite free bytes (inspect via df -i).
      Why this gets asked: foundational question during incident triage interviews.
    6. What is an associative array and in which Bash version was it introduced?
      declare -A m; m[key]=val implements key-value dictionaries; introduced in Bash 4.0.
      Why this gets asked: critical for macOS compatibility, which ships with Bash 3.2 by default.
    7. What does ${var:?message} do?
      Aborts script execution with an error printing message if the variable is unset or null.
      Why this gets asked: concise idiomatic assertion for mandatory script parameters.
    8. How does ${var%.txt} differ from ${var#*/}?
      The former strips matching suffix patterns; the latter strips matching prefix patterns; doubling the symbol enables greedy matching.
      Why this gets asked: pure builtin string manipulation replacing external subshell calls like basename.
    9. How do you validate a string against a regular expression without grep?
      [[ $s =~ ^v([0-9]+) ]]; captured groups are stored in ${BASH_REMATCH[@]}. The right-hand regex must not be quoted - quoting forces literal string comparison.
      Why this gets asked: tests knowledge of built-in pattern matching and a subtle quoting trap.
    10. Why is eval considered hazardous?
      It executes a string as code after performing all expansions, converting untrusted input into executed commands. Safer alternatives exist almost always: arrays for argument lists, printf -v, or namerefs (declare -n).
      Why this gets asked: checks whether you can spot remote code injection vulnerabilities.

    Processes, pipelines, and redirections (21–30) #

    1. In what order does Bash execute expansions?
      Five distinct stages: brace expansion; then a single left-to-right pass performing tilde expansion, parameter expansion, command substitution, arithmetic expansion, and process substitution; followed by word splitting; pathname expansion; and quote removal. That parameter and arithmetic expansion occur in the same pass is proven by x=1; echo $((x=2)) $x, which outputs 2 2.
      Why this gets asked: explains nearly all shell quirks at once; claiming “eight sequential steps” is a common inaccuracy.
    2. Why does {1..$n} fail to expand?
      Brace expansion executes before parameter expansion, so $n has not yet been replaced with its value.
      Why this gets asked: tests understanding of expansion precedence rather than mere syntax memorization.
    3. How does cmd >log 2>&1 differ from cmd 2>&1 >log?
      In the former, both descriptors redirect to the file; in the latter, stderr duplicates stdout's initial target (the terminal), and only stdout redirects to the file.
      Why this gets asked: classic test of file descriptor duplication mechanics.
    4. What is a here-document and what is its primary pitfall?
      <<EOF feeds multiline text to stdin; <<< feeds a single string. The pitfall is delimiter quoting: with 'EOF' text is literal; without quotes, $var and $(cmd) expand, silently corrupting embedded dollar signs in SQL or configs.
      Why this gets asked: checks whether you know when content mutates during ingestion.
    5. Why is a variable modified inside a loop after | empty outside the loop?
      Pipeline stages execute inside subshells; environment mutations do not propagate back to the parent process.
      Why this gets asked: one of the most frequently discussed Bash architectural puzzles.
    6. How do you stream a command's output into a loop without spawning a subshell?
      Using process substitution: while read -r l; do …; done < <(cmd).
      Why this gets asked: tests mastery of process substitution <( ) - a hallmark of seniority.
    7. How does exec without arguments differ from exec cmd?
      Without a command, it reconfigures file descriptors for the current shell; with a command, it replaces the current process image without spawning a new PID.
      Why this gets asked: critical for container entrypoint wrappers.
    8. How do you enforce a execution time ceiling on a command?
      timeout 30 cmd; on expiration, it exits with status code 124.
      Why this gets asked: mandatory safeguard for network and external service operations.
    9. How do you execute a process so it survives terminal session termination?
      nohup cmd &, setsid, or a terminal multiplexer; in systemd, launch it as a dedicated service unit.
      Why this gets asked: tests understanding of controlling terminals and SIGHUP signals.
    10. What does wait -n do?
      It pauses until any single background job completes rather than waiting for all jobs (Bash 4.3+).
      Why this gets asked: necessary for implementing custom worker pool limits.

    Files, concurrency, and locking (31–40) #

    1. Why should temporary files always be generated via mktemp?
      It guarantees cryptographically random filenames and restrictive file permissions; predictable paths in /tmp introduce race conditions and symlink hijacking exploits.
      Why this gets asked: tests awareness of both operational reliability and system security.
    2. How do you prevent concurrent execution of multiple script instances?
      Bind flock to a file descriptor: the lock releases automatically upon process termination, unlike brittle flag files.
      Why this gets asked: essential requirement for cron jobs and schedulers.
    3. How does mv differ from cp regarding atomicity?
      Renaming within the same filesystem is atomic; copying is not, exposing partially written intermediate files to concurrent readers.
      Why this gets asked: foundational pattern for zero-downtime deployment cutovers and config generation.
    4. How do you atomically switch a symlink to point to a new release?
      ln -sfn new tmp && mv -T tmp current - updates the symlink target in a single atomic filesystem operation.
      Why this gets asked: checks whether you consider intermediate system states during deployments.
    5. How do you safely process filenames containing spaces and newlines?
      Use null delimiters: find … -print0 piped to xargs -0 or parsed with read -d ''.
      Why this gets asked: indicates real-world experience handling unhygienic filesystem data.
    6. Why is xargs -P superior to looping with background &?
      It throttles maximum concurrent workers and returns a non-zero exit code if any worker job fails.
      Why this gets asked: standard production technique for managed parallelism.
    7. How do you verify whether a background process failed?
      Capture its PID via $! and invoke wait $PID - returning the exit status. In contrast, argumentless wait always returns 0, even if background jobs failed.
      Why this gets asked: verifies understanding that bare wait silently swallows failures.
    8. How does locale affect sort, grep, and ranges like [a-z]?
      Collation order and range definitions vary across locales, causing identical scripts to produce diverging results across hosts. Enforce predictability by setting LC_ALL=C.
      Why this gets asked: notorious source of “works on my machine” discrepancies that are difficult to isolate without deep knowledge.
    9. How does find -exec cmd {} + differ from -exec cmd {} \;?
      \; spawns a separate process per matched file; + aggregates files into batches similar to xargs. Across thousands of files, + executes orders of magnitude faster while handling spaces safely.
      Why this gets asked: evaluates understanding of process spawning overhead.
    10. What happens to for f in *.log if no matching files exist, and what do nullglob and failglob change?
      By default, the pattern remains an unexpanded literal string *.log, causing the loop to execute once on a non-existent path. shopt -s nullglob expands unmatched globs to an empty list; failglob raises an error.
      Why this gets asked: classic trap where scripts erroneously process missing files.

    CI, containers, systemd, and secrets (41–50) #

    1. With what flags does CI execute a run: step?
      In GitHub Actions without an explicit shell:, it executes bash -e {0}; with shell: bash, it runs bash --noprofile --norc -eo pipefail {0}. The -u flag is never enabled automatically.
      Why this gets asked: checks whether you inspect runner documentation rather than assuming shell flags.
    2. Why is an export in one CI step invisible in subsequent steps?
      Each step executes in an isolated process; persist environment variables across steps by writing to runner files like $GITHUB_ENV.
      Why this gets asked: textbook mistake when transitioning from local development to CI automation.
    3. Why does a container fail to shut down gracefully upon docker stop?
      When using the shell form of ENTRYPOINT, PID 1 is the shell process, which fails to forward SIGTERM to application children. Use the exec array form or prepend exec in entrypoint scripts.
      Why this gets asked: favorite interview topic in container and Kubernetes assessments.
    4. Why do scripts fail when running in Alpine Linux images?
      Alpine uses busybox ash as /bin/sh; Bash is not installed by default, and core utility options diverge from GNU coreutils.
      Why this gets asked: evaluates awareness of distribution differences in minimal container images.
    5. Why do redirections fail inside systemd ExecStart directives?
      Directives are parsed directly by systemd rather than passed through a shell; wrap commands explicitly with /bin/bash -c '…'.
      Why this gets asked: frequent pitfall when authoring systemd service units.
    6. How do you securely supply secrets to a command?
      Pass them via stdin, credentials files, or environment variables - never as command arguments, which are visible in ps to all local users.
      Why this gets asked: non-negotiable security baseline evaluated in every engineering interview.
    7. Why is set -x dangerous in CI environments?
      Execution tracing prints expanded variables, exposing secrets directly in CI build logs, while CI masking only redacts exact string matches.
      Why this gets asked: tests whether you treat build logs as public audit surfaces.
    8. How does /bin/sh differ from /bin/bash on Debian/Ubuntu systems?
      sh symlinks to dash: lacking arrays, [[ ]], process substitution, and ${v//a/b} pattern replacement. Contrary to popular misconception, local is supported in dash.
      Why this gets asked: core portability knowledge; even seasoned engineers trip on local support in dash.
    9. How do you validate a shell script without executing it?
      bash -n script.sh checks syntax; shellcheck performs deep static analysis catching semantic bugs and pitfalls.
      Why this gets asked: checks for ingrained static analysis and linting habits.
    10. What is # shellcheck disable=SCxxxx and how should it be applied?
      It suppresses a specific rule for the immediate next line; applying global file-level suppressions almost always masks legitimate defects.
      Why this gets asked: demonstrates your engineering posture toward automated quality gates.
