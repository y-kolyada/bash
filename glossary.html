    Словарь понятий

    Шесть слов, которые на остальных страницах уже не объясняются. Каждое — не определение для экзамена, а механика, незнание которой стоит инцидента.

    Главная мысль словаря #

    Словарь здесь нужен не для заучивания, а для устранения двусмысленности: пока «ошибка» и «ненулевой код возврата» для вас разные вещи, спорить о надёжности скрипта бессмысленно. В каждой карточке три слоя: одна фраза для узнавания, абзац механики и строка о том, где это встретилось впервые. Карточки намеренно короткие — плотность важнее полноты, а полное описание есть в man bash.

    Shebang #!/usr/bin/env bash #

    Первая строка скрипта, указывающая ядру, каким интерпретатором его запускать.

    Без неё скрипт выполнит та оболочка, из которой его вызвали, — и на машине с dash вместо bash массивы и [[ ]] перестанут работать. Форма через env ищет bash в PATH, а не только в /bin: на macOS и в BSD он лежит в другом месте.

    Код возврата $? #

    Число от 0 до 255, которым команда сообщает об успехе (0) или об ошибке (не 0).

    Это единственный машинный признак провала: текст в stderr — для человека, код возврата — для автоматики. Отсюда правило: сообщение об ошибке без ненулевого кода означает, что CI увидит зелёное. ./check.sh на этом и построен.

    🎯 Где встретилось впервые: Вход · Семь целей

    Конвейер a | b #

    Цепочка команд, где вывод одной становится вводом следующей.

    Звенья запускаются одновременно, а не по очереди, и каждое живёт в своём процессе. Код возврата конвейера по умолчанию берётся только у последнего звена — поэтому ложная_команда | tee log вернёт 0. Весь набор кодов лежит в ${PIPESTATUS[@]}.

    🎯 Где встретилось впервые: Вход · Три уровня

    Строгий режим set -euo pipefail #

    Три предохранителя: падать на ошибке, падать на необъявленной переменной, не терять ошибку в конвейере.

    -e — выход при ненулевом коде, но не внутри условий, && и функций, вызванных в условии. -u превращает опечатку в имени переменной в остановку, а не в пустую строку. -o pipefail отдаёт код первого упавшего звена конвейера. Это минимум гигиены, а не гарантия надёжности.

    🎯 Где встретилось впервые: Вход · Три уровня

    Словоделение "$var" #

    Разбиение результата подстановки на отдельные слова по пробелам и переводам строк.

    Bash подставляет значение переменной, а затем режет его. Поэтому путь /home/My Files/a.txt без кавычек превращается в два аргумента, и команда удаления удалит не то, что вы имели в виду. Кавычки вокруг подстановки — не стиль, а защита: это же первая ошибка, которую регулярно делают ИИ-агенты.

    🎯 Где встретилось впервые: Вход · Семь целей

    Сабшелл ( ... ) #

    Дочерний процесс оболочки: он наследует окружение, но его изменения наружу не возвращаются.

    Отсюда классическая загадка: цикл после конвейера считает строки, а после его завершения переменная снова пуста — цикл выполнялся в сабшелле. Понимание границы процесса объясняет половину «мистических» поломок в скриптах, включая потерянный cd.
