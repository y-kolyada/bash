    Bash: what the assessment asks, and what production needs

    A Bash reference and assessment site for engineers preparing for a certification, a technical interview, or simply done with guessing. Six sections, three maturity levels, 150 questions with answers.

    The key idea of this site #

    Everyone knows Bash and almost nobody does — it looks simple right up to the first production incident where a script silently swallowed an error and exited zero. This site treats Bash as a system rather than a list of commands: what it is made of, where its seams with other tools are, where it is weaker than the alternatives, and which of its defaults are dangerous. A separate thread runs through it: working on Bash together with AI agents. A model writes shell scripts confidently and drops quoting, word splitting and exit codes just as confidently, so reading its output stays your job. The material is organised by three maturity levels — Noob, Pro, IGL — so you see not only the answer but your next horizon. Everything is kept short: a paragraph either changes a decision of yours, or it is not here.

    Three levels, and why they are kept apart #

    Noob — you run scripts and occasionally edit them. The level's job: remove the magic.
    Pro — you write scripts that run on other people's machines. The level's job: remove silent failures.
    IGL — you decide whether a script should exist at all. The level's job: see the cost of that decision a year ahead.

    The same question has different correct answers at different levels. That is why the questions are separated rather than merely sorted by difficulty.

    Why levels are not the same as difficulty

    Question: “what does set -e do?”

    Noob: it aborts the script on the first error. Pro: it aborts — but not inside a PipelineA chain of commands joined by |. By default the exit code comes from the last stage only — the first stage's failure is lost.Open in glossary 📖 and not in a condition, which is why you need set -euo pipefailThree fuses: fail on error, fail on an unset variable, do not lose a failure inside a pipeline.Open in glossary 📖. IGL: it grants a false sense of safety — on long logic that is the signal to move to a language with real exceptions.

    The toolchain this site is built with #

    Simple Web Architecture: static HTML and CSS, around 160 lines of vanilla JavaScript, zero backend, zero build step. Pages sit flat in the repository root, with no subfolders — that way links do not break on static hosting.

    The site has its own task, written before the AI did any work — zadanie-1.md; a record of what actually happened — zapis-1.md; and a list of what was deferred, with a reason per line — potom.md. The check is ./check.sh, and it answers GREEN or RED. Phone width is measured by node glaza.mjs index.html: it finds whatever overflows the right edge and returns an exit code, which makes it usable as an automated check.
