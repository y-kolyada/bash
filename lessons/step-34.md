## Задание 34

**Исполнитель:** Claude Code (Opus 5). **Основание:** росток `seed/swa` собран из эталона и по
дороге получил три улучшения, которых в эталоне нет. Долг ростка перед эталоном, названный в
записи задания 33: пока он не закрыт, **оснастка разошлась в первый же день.**

**Хочу:** `assets/` и `tools/` эталона байт в байт совпадают с ростком. Всё, что отличает сайт,
лежит в одном файле `site.conf`.

**Откуда это.** Измерено сравнением файлов:

```
swa.js            расходятся, 20 строк    ключи хранилища вшиты как swa-bash-*
check-pages.mjs   расходятся, 50 строк    два исправления и слово поиска из site.conf
build-nav.py      расходятся,  6 строк    номер версии и data-site из site.conf
build-meta.py     расходятся,  7 строк    адрес и имя сайта из site.conf
style.css         одинаковы
check-vocab.py    одинаковы
check-voice.py    одинаковы
```

Три улучшения ростка, которые эталон должен получить:

1. **Движок читает имя сайта из разметки** (`<html data-site="bash">`), поэтому `assets/swa.js`
   одинаков на всех сайтах серии. Ключи хранилища остаются теми же - `swa-bash-*`, - но строятся
   одним помощником, а не вписаны шесть раз.
2. **Браузерная проверка не требует прокрутки от страницы короче окна.** Эталон этого дефекта не
   видел только потому, что все его страницы длинные.
3. **Слово дымового теста поиска не вшито.** В эталоне это `pipefail`; станет строкой
   `search = pipefail` в `site.conf`.

Плюс обратное улучшение, которое эталон отдаёт ростку: атрибут `data-site` **ставит генератор
оболочки**, а не штамповщик, - тогда он появляется на страницах сам и не может потеряться.

**Предикаты:**

1. **Оснастка совпадает дословно.** `diff` между эталоном и ростком пуст для `assets/swa.js`,
   `assets/style.css`, `tools/build-nav.py`, `tools/build-meta.py`, `tools/check-pages.mjs`,
   `tools/check-vocab.py`, `tools/check-voice.py`, `tools/check-links.py`, `tools/check-text.py`,
   `tools/check-struct.py`, `tools/build-search.py`, `tools/siteconf.py`.
   **Чем проверяется:** машиной - `diff -q` по списку возвращает «одинаковы» для каждого файла.

2. **Имя сайта больше не вшито нигде, кроме `site.conf`.** В `assets/` и `tools/` нет строк
   `devops-bash`, `y-kolyada.github.io` и `swa-bash-`; все 68 страниц несут
   `<html lang="..." data-site="bash">`, и его ставит `build-nav.py`.
   **Чем проверяется:** машиной - `grep -rn 'devops-bash\|y-kolyada.github.io\|swa-bash-' assets/ tools/`
   не находит ничего; `grep -c 'data-site="bash"' */*.html` даёт 68.

3. **Сайт остался тем же для читателя.** Восемь проверок зелёные; настройка темы и размера
   шрифта, сохранённая до правки, читается после неё (ключи не переименовались); поиск находит
   слово из `site.conf`.
   **Чем проверяется:** машиной - `./check.sh` печатает ЗЕЛЁНОЕ; браузерной пробой: ключ
   `swa-bash-theme` в хранилище после переключения темы.

## Решения Архитектора

| Вопрос | Решение |
| :-- | :-- |
| Направление | Эталон подтягивается к ростку, а не наоборот: росток уже разошёлся с пятью новыми сайтами, и он теперь источник. |
| Ключи хранилища | **Не переименовываются.** `swa-bash-*` остаются: у читателя в браузере уже лежат его настройки. |
| Номер версии | `version = 13` в `site.conf`, как сейчас. Релиз 14 поднимет его по ритуалу. |
| Две проверки темы | `check-claims.sh` и `check-examples.sh` с фикстурами остаются только в эталоне: механика общая, интерпретатор нет. |
| Коммиты | Локально; push и мерж делает Архитектор. |
