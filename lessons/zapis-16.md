## Что запуск опроверг и что исправлено на страницах

Три находки. Каждая исправлена **в двух языках сразу**, потому что код у всех языков один.

| Где | Что было | Что показал запуск | Что стало |
| :-- | :-- | :-- | :-- |
| `10` · Цикл по файлам | `for f in $(ls *.log); do …` | многоточие - не код: блок нельзя ни исполнить, ни разобрать | цикл дописан целиком, и теперь он сам печатает поломку |
| `11` · Параллельная обработка | `for f in …; do work "$f" &` | то же многоточие | `for f in logs/*.log` |
| `12` · Радиус поражения | `(( ${#list[@]} > 20 )) && { ...; exit 2; }` | когда условие ложно, скрипт заканчивается кодом **1**: последняя команда - неудавшийся `&&`-список | страж переписан через `if ... then ... fi` |

Третья находка - самая полезная. Пример учил ограничивать объём за один запуск, а сам, если
скопировать его в конец скрипта, сообщал об отказе на нормальной работе. Проверка запуском
нашла то, что перечитыванием не находится.

**Что печатает терминал** (блок `10-5`, где заготовка создала `old file.log` и `app.log`):

```
обрабатываю: app.log
обрабатываю: old file.log     <- правильный цикл: имя целиком
обрабатываю: app.log
обрабатываю: old              <- $(ls): имя разрезано по пробелу
обрабатываю: file.log
```

Страница утверждает именно это - теперь утверждение подтверждено выводом, а не доверием.

## Как устроена проверка

Пометка живёт в разметке, а не в скрипте: род блока виден тому, кто читает страницу.
Заготовка - обычная прелюдия на Bash, которая дописывается перед блоком. Строки вида
`#@ ключ: значение` читает запускалка, а не Bash:

| Ключ | Зачем |
| :-- | :-- |
| `#@ args:` | аргументы блоку |
| `#@ code:` | ожидаемый код возврата (по умолчанию 0) |
| `#@ want:` | подстрока, которая обязана быть в выводе; строк может быть несколько |
| `#@ then:` | команда после блока; её отказ - отказ блока |

`#@ then:` оказался главным инструментом честности. Он проверяет **утверждение страницы**, а
не работоспособность Bash:

- `10-3`: страница говорит, что `rm -f $file` без кавычек удалит «мой» и «отчёт.txt», то есть
  не сам файл. После блока выполняется `test -e "мой отчёт.txt"` - файл на месте.
- `11-3`: `run rm -rf "$target"` в режиме `-n` обязан только напечатать `DRY: rm -rf victim`.
  После блока `test -e victim` - файл не тронут.
- `12-3`: после блока в `done.log` ровно одна строка - работа выполнена один раз.
- `11-1` и `11-7` переведены из первого рода во второй именно поэтому: ловушка, которая ни разу
  не сработала, ничего не доказывает. Теперь после блока выполняется `false`, и терминал
  печатает `ОТКАЗ: строка 17, код 1` - номер строки, за которым и ставят `trap ERR`.

Каждый блок работает в своём временном каталоге, и `TMPDIR` указывает туда же - поэтому даже
`mktemp -d` из примера `11-2` остаётся внутри. Рядом с сайтом не создаётся ничего.
