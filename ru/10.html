    Примеры · Noob

    Шесть разборов для уровня «запускаю и иногда правлю». Задача уровня - убрать магию: каждая строка здесь объяснена до причины, а не до рецепта.

    Главная мысль страницы #

    На этом уровне важно не количество выученных команд, а понимание, почему скрипт ведёт себя именно так. Шесть разборов ниже закрывают те места, где новичок спотыкается чаще всего: запуск файла и права, кавычки вокруг переменных, проверка перед действием, цикл по файлам, аргументы и код возврата, чтение файла построчно. В каждом разборе сначала задача, потом код, потом объяснение - и объяснение здесь главное. Выучить эти шесть вещей можно за вечер; понять их - значит перестать бояться чужих скриптов.

    1 · Первый скрипт: файл, права, запуск #

    Задача: превратить две команды в программу, которую можно запускать.

    #!/usr/bin/env bash
echo "сегодня: $(date +%F)"
df -h / | tail -1
    chmod +x hello.sh   # один раз
./hello.sh          # запуск
bash hello.sh       # без прав
    Почему так: Файл со скриптом - обычный текст; исполняемым его делает бит прав, а не расширение. ./ перед именем обязательно: без него оболочка ищет программу в PATH, а текущего каталога там нет - отсюда «command not found» на файл, который лежит рядом. bash hello.sh работает и без прав, потому что исполняется bash, а скрипт - его аргумент.

    2 · Переменные и кавычки #

    Задача: вывести имя файла, в котором есть пробел.

    file="мой отчёт.txt"

echo $file     # мой отчёт.txt - повезло
ls $file       # ОШИБКА: два файла
ls "$file"     # правильно

rm -f $file    # удалит "мой" и "отчёт.txt"
    Почему так: Bash подставляет значение переменной, а потом режет его по пробелам. echo этого не показывает, потому что печатает все аргументы через пробел - и создаёт ложное ощущение, что всё хорошо. Кавычки отменяют разрезание. Правило простое: подстановка без кавычек - осознанное решение, а не умолчание.

    3 · Условия: проверить, прежде чем делать #

    Задача: скопировать файл, если он существует, иначе понятно сказать об этом.

    src="data.csv"

if [ -f "$src" ]; then
  cp "$src" backup/
else
  echo "нет файла: $src" >&2
  exit 1
fi
    Почему так: [ -f ] проверяет, что это существующий обычный файл; -d - каталог, -r - доступен на чтение, -z - строка пуста. Сообщение об ошибке уходит в >&2 - в поток ошибок, а не в результат. И выход ненулевым кодом обязателен: без него тот, кто вызвал ваш скрипт, будет считать, что всё прошло успешно.

    4 · Цикл по файлам (и почему не через ls) #

    Задача: обработать все .log в каталоге.

    # правильно
for f in *.log; do
  [ -e "$f" ] || continue   # ни одного
  echo "обрабатываю: $f"
done

# неправильно, хотя встречается часто
for f in $(ls *.log); do …
    Почему так: Шаблон *.log раскрывает сама оболочка, сохраняя имена целиком - даже с пробелами. $(ls) отдаёт один текст, который снова режется по пробелам, и имя «old file.log» превращается в два несуществующих файла. Проверка [ -e "$f" ] нужна, потому что если ни один файл не подошёл, шаблон остаётся сам собой и цикл выполнится один раз со строкой *.log.

    5 · Аргументы и код возврата #

    Задача: принять имя от пользователя и сообщить, удалось ли.

    #!/usr/bin/env bash
name="$1"

if [ -z "$name" ]; then
  echo "usage: $0 <имя>" >&2
  exit 2
fi

grep -q "$name" users.txt
echo "код возврата: $?"
    Почему так: $1 - первый аргумент, $# - их количество, $0 - имя самого скрипта. $? хранит код возврата последней выполненной команды, и это единственный способ узнать у команды, получилось ли: grep возвращает 0, когда нашёл, и 1, когда нет. Ноль - успех, любое другое число - нет; код 2 обычно означает «неправильный вызов».

    6 · Чтение файла построчно #

    Задача: пройти по строкам файла и что-то с ними сделать.

    while IFS= read -r line; do
  echo "строка: $line"
done < names.txt
    Почему так: Три детали, каждая из которых нужна. IFS= перед read сохраняет пробелы в начале и конце строки. -r запрещает трактовать обратную косую черту как экранирование - без него C:\new превратится в строку с переводом строки. И перенаправление < файл стоит после done, а не перед while.

    Артефакты: что у вас есть после этой страницы #

    Чтение >> Ваш квант времени жизни · Партнёрство достоинства вместе с AI · Перестройка вашей нейросети

    Шесть объяснённых мест вместо шести заученных команд. Время потрачено не зря, если вы теперь знаете, почему ./ обязательно, почему кавычки не украшение и почему $(ls) в цикле - ошибка. Это и есть перестройка нейросети: чужой скрипт перестаёт быть заклинанием и становится текстом, который можно прочитать.

    1. Права и ./ - почему файл рядом «не найден».
    2. Кавычки как защита от разрезания по пробелам.
    3. Проверка перед действием и выход ненулевым кодом.
    4. Цикл по шаблону, а не по выводу ls.
    5. $1, $#, $? - аргументы и код возврата.
    6. while IFS= read -r и зачем нужна каждая часть.
