    Словарь понятий

    Слов: 1723

    Двадцать два понятия, которые на страницах сайта уже не объясняются. Каждое - не определение для экзамена, а механика, незнание которой стоит инцидента.

    Главная мысль словаря #

    Словарь здесь нужен не для заучивания, а для устранения двусмысленности: пока «ошибка» и «ненулевой код возврата» для вас разные вещи, спорить о надёжности скрипта бессмысленно. Понятия разложены по трём уровням, как устроен сам сайт: механика - как оболочка выполняет строку, практика - как писать скрипт, который переживёт эксплуатацию, решения - чем ограничен худший случай. В каждой карточке три слоя: одна фраза для узнавания, абзац механики и ссылка на раздел, где понятие разобрано подробно. Карточки намеренно короткие: плотность важнее полноты, а полное описание есть в man bash.

    Механика: как оболочка выполняет строку #

    Shebang #!/usr/bin/env bash #

    Первая строка скрипта, указывающая ядру, каким интерпретатором его запускать.

    Без неё скрипт выполнит та оболочка, из которой его вызвали, - и на машине, где sh это dash, массивы и [[ ]] перестанут работать. Форма через env ищет bash в PATH, а не только в /bin: на macOS и в BSD он лежит в другом месте.

    Где встретилось впервые: Написание скриптов · Скелет

    Режимы оболочки login · interactive #

    Одна программа Bash в двух ролях: оболочка, с которой работает человек, и интерпретатор, который выполняет файл.

    Интерактивная оболочка читает ~/.bashrc, знает псевдонимы и историю; login-оболочка (вход по ssh, su -) читает ~/.bash_profile; скрипт не читает ни того, ни другого. Отсюда «в терминале работает, в cron нет»: PATH и псевдонимы из ваших файлов настроек до скрипта не доходят.

    Где встретилось впервые: Написание скриптов · Два режима

    PATH $PATH #

    Список каталогов через двоеточие, в которых оболочка ищет программу по имени.

    Текущего каталога в нём нет, поэтому файл рядом запускают как ./script.sh. Порядок важен: найдена будет первая подходящая программа, и type cmd покажет, какая именно. В cron и в CI PATH короче вашего - скрипт, который на это рассчитывает, сломается там первым.

    Где встретилось впервые: Примеры · Noob · Первый скрипт

    Переменная окружения export VAR=value #

    Переменная, которую оболочка передаёт дочерним процессам.

    Обычное присваивание VAR=value видно только текущей оболочке; export помечает переменную для наследования. Наследование идёт только вниз: дочерний процесс не может изменить окружение родителя. Поэтому значение из одного шага CI не видно в следующем - каждый шаг это новый процесс.

    Где встретилось впервые: Ключевые компоненты · Переменные

    Шаблон имён *.log · ?.txt · [ab]* #

    Выражение, которое оболочка раскрывает в список подходящих имён файлов до запуска команды.

    Раскрытие делает сама оболочка, а не программа, поэтому имена с пробелами сохраняются целиком - в отличие от $(ls). Если ни один файл не подошёл, шаблон по умолчанию остаётся самим собой, и цикл выполнится один раз со строкой *.log; shopt -s nullglob меняет это поведение на пустой список.

    Где встретилось впервые: Ключевые компоненты · Разбор командной строки

    Словоделение "$var" #

    Разбиение результата подстановки на отдельные слова по пробелам и переводам строк.

    Bash подставляет значение переменной, а затем режет его. Поэтому путь /home/My Files/a.txt без кавычек превращается в два аргумента, и команда удаления удалит не то, что вы имели в виду. Кавычки вокруг подстановки - не стиль, а защита; и это первая ошибка, которую регулярно делают ИИ-агенты.

    Где встретилось впервые: Ключевые компоненты · Раскрытия и словоделение

    IFS IFS=$'\n\t' #

    Набор символов, по которым оболочка режет текст на слова.

    По умолчанию это пробел, табуляция и перевод строки. Сужение IFS до перевода строки и табуляции в начале скрипта убирает разрезание по пробелам там, где оно почти никогда не нужно. В конструкции IFS= read -r line пустое значение действует только на одну команду и сохраняет пробелы по краям строки.

    Где встретилось впервые: Ключевые компоненты · Раскрытия и словоделение

    Поток и дескриптор 0 · 1 · 2 #

    Пронумерованный канал ввода или вывода процесса: 0 - ввод, 1 - результат, 2 - ошибки и всё остальное.

    Дескриптор - это номер, поток - то, что по нему течёт. Разделение 1 и 2 - условие работы в конвейере: следующая команда читает только поток 1, и сообщение «начинаю работу», отправленное туда, окажется в её данных. Отсюда правило: результат в stdout, остальное в stderr, статус - кодом возврата.

    Где встретилось впервые: Ключевые компоненты · Процессы и перенаправления

    Перенаправление > · >> · 2>&1 #

    Указание оболочке, куда направить поток процесса вместо терминала.

    > перезаписывает файл, >> дописывает, 2>&1 направляет ошибки туда же, куда сейчас идёт результат. Перенаправления применяются слева направо, поэтому cmd >log 2>&1 и cmd 2>&1 >log дают разный результат: во втором случае ошибки остаются в терминале.

    Где встретилось впервые: Ключевые компоненты · Процессы и перенаправления

    Конвейер a | b #

    Цепочка команд, где вывод одной становится вводом следующей.

    Звенья запускаются одновременно, а не по очереди, и каждое живёт в своём процессе. Код возврата конвейера по умолчанию берётся только у последнего звена - поэтому ложная_команда | tee log вернёт 0. Весь набор кодов лежит в ${PIPESTATUS[@]}.

    Где встретилось впервые: Ключевые компоненты · Конвейеры и коды возврата

    Код возврата $? #

    Число от 0 до 255, которым команда сообщает об успехе (0) или об ошибке (не 0).

    Это единственный машинный признак провала: текст в stderr - для человека, код возврата - для автоматики. Сообщение об ошибке без ненулевого кода означает, что CI увидит зелёное. Коды 126, 127 и 128+N выдаёт сама оболочка: «не исполняемо», «не найдено», «убито сигналом N».

    Где встретилось впервые: Ключевые компоненты · Конвейеры и коды возврата

    Сабшелл ( ... ) #

    Дочерний процесс оболочки: он наследует окружение, но его изменения наружу не возвращаются.

    Отсюда классическая загадка: цикл после конвейера считает строки, а после его завершения переменная снова пуста - цикл выполнялся в сабшелле. Подоболочку создают круглые скобки, звенья конвейера и подстановка $( ); фигурные скобки - нет. Понимание этой границы объясняет и потерянный cd, и exit, который не завершил скрипт.

    Где встретилось впервые: Ключевые компоненты · Переменные и области видимости

    Сигнал SIGINT · SIGTERM · SIGKILL #

    Асинхронное сообщение процессу от ядра, другого процесса или терминала.

    SIGINT посылает Ctrl+C, SIGTERM - kill и остановка контейнера, SIGKILL - kill -9. Первые два процесс может перехватить и корректно завершиться; SIGKILL - нет, это свойство ядра. Процесс, убитый сигналом N, возвращает код 128+N: 130 для Ctrl+C, 143 для SIGTERM.

    Где встретилось впервые: Ключевые компоненты · Сигналы и ловушки

    Ловушка trap … EXIT #

    Обработчик, который оболочка выполняет при сигнале или при наступлении события.

    Ловушка на EXIT срабатывает при любом завершении, которое оболочка успевает заметить, - успешном, по ошибке, по прерыванию - и поэтому остаётся единственным надёжным способом убрать за собой. Исключение - SIGKILL: процесс уничтожает ядро, и ловушка не выполняется вовсе. Ловушка на ERR срабатывает на ошибке; чтобы её наследовали функции и подоболочки, нужен set -E.

    Где встретилось впервые: Ключевые компоненты · Сигналы и ловушки

    POSIX и bashism #!/bin/sh #

    POSIX - стандарт, общий для всех оболочек; bashism - возможность, которая есть только в Bash.

    Массивы, [[ ]], подстановка процессов и ${v//a/b} - bashism: в dash, который стоит как /bin/sh в Debian и Ubuntu, их нет. Выбор делают один раз и явно: либо #!/usr/bin/env bash и все удобства, либо #!/bin/sh, проверка через shellcheck -s sh и отказ от удобств.

    Практика: скрипт, который переживёт эксплуатацию #

    Строгий режим set -euo pipefail #

    Три предохранителя: падать на ошибке, падать на необъявленной переменной, не терять ошибку в конвейере.

    -e - выход при ненулевом коде, но не внутри условий, &&, || и функций, вызванных в условии, и не в local x=$(cmd). -u превращает опечатку в имени переменной в остановку, а не в пустую строку. -o pipefail отдаёт код последнего (самого правого) упавшего звена конвейера. Это минимум гигиены, а не гарантия надёжности.

    Где встретилось впервые: Написание скриптов · Скелет

    Режим проверки --dry-run #

    Запуск, при котором скрипт печатает, что сделал бы, и ничего не делает.

    Ценен, только если устроен структурно: каждая изменяющая команда проходит через одну обёртку, которая в этом режиме печатает вместо выполнения. Добавленный потом, он покрывает не все опасные ветки. И обёртка не видит перенаправлений: run cmd > file затрёт файл и в режиме проверки, потому что > выполняет оболочка до входа в функцию. Для агента это главный способ проверить логику без последствий, для человека - способ принять работу до того, как она что-то сломала.

    Где встретилось впервые: Примеры · Pro · Опции и --dry-run

    Идемпотентность mkdir -p · ln -sfn #

    Свойство операции: повторный запуск не меняет результат и не ломает состояние.

    В автоматике повтор неизбежен: таймаут, перезапуск узла, двойное событие, агент, который повторил без вопроса. mkdir -p, ln -sfn, rsync идемпотентны; mkdir без ключа и >> в журнал - нет. Для неидемпотентной работы вводят идентификатор операции и выполняют её только при его отсутствии в журнале выполненного.

    Где встретилось впервые: Написание скриптов · Идемпотентность и уборка

    Атомарность mv -T #

    Свойство операции: она либо выполнена целиком, либо не выполнена вовсе, без видимого промежуточного состояния.

    Переименование в пределах одной файловой системы атомарно, копирование - нет. Поэтому результат сначала готовят во временном месте, а потом одним mv ставят на место; а симлинк на новый релиз переключают через ln -sfn во временное имя и mv -T поверх текущего. Пара rm и ln -s атомарной не является: между ними ссылки нет вовсе.

    Где встретилось впервые: Практики DevOps · Деплой и откат

    Блокировка flock #

    Механизм, не дающий двум экземплярам одной задачи работать одновременно.

    flock держит блокировку на открытом дескрипторе, и она снимается сама, когда процесс завершается, - в том числе аварийно. Самодельный файл-флаг этим свойством не обладает: после падения он остаётся на диске и блокирует запуски навсегда. Типичное место применения - задача из cron, которая может не успеть до следующего запуска.

    Решения: чем ограничен худший случай #

    Контракт инструмента stdout · stderr · коды · --json #

    Объявленное поведение скрипта, на которое опираются вызывающие его программы.

    В контракт входят назначение потоков, набор кодов возврата, формат машинного вывода, наличие режима проверки и правила совместимости. Реализацию можно переписать, контракт - нельзя: на него уже кто-то опирается, и любое его изменение ломает вызывающего, которого вы не знаете. Собственные коды берут из диапазона 3-63 или по sysexits.h, не занимая 126, 127 и 128+N.

    Где встретилось впервые: Примеры · IGL · Контракт скрипта

    Радиус поражения blast radius #

    Максимальный ущерб, который скрипт нанесёт, если ошибётся.

    Проектируется от худшего случая, а не от ожидаемого. Его ограничивают два условия в начале скрипта: белый список области действия - работать только в заданном пути или наборе ресурсов - и предел на объём за один запуск. Скрипт, который «нашёл» три тысячи объектов вместо пяти, должен остановиться и позвать человека: так катастрофа превращается в инцидент.

    Артефакты: что у вас есть после словаря #

    Чтение >> Ваш квант времени жизни · Партнёрство достоинства вместе с AI · Перестройка вашей нейросети

    Общий язык вместо двадцати двух определений. Время на эту страницу потрачено не зря, если в разговоре о скрипте вы и собеседник имеете в виду одно и то же, когда говорите «идемпотентно», «атомарно» или «потеряли код возврата». Это и есть перестройка нейросети: термин перестаёт быть словом и становится инструментом, которым можно спорить по существу.

    1. Пятнадцать понятий механики - от shebang до POSIX, в порядке, в котором оболочка проходит путь от первой строки файла до завершения процесса.
    2. Пять понятий практики - строгий режим, режим проверки, идемпотентность, атомарность, блокировка.
    3. Два понятия решений - контракт инструмента и радиус поражения, которых нет в man bash.
